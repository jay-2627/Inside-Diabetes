TASK 1 — VERIFY EXISTING MODELS

A comprehensive audit of the model artifacts and pipeline scripts revealed the following architectural state:

  1. Models Actually Trained: Four distinct models are fully trained and pickled in model/:
    • XGBoost Classifier (model/xgboost_model.pkl): Gradient Boosted Decision Trees (50 estimators, max depth 3, scale_pos_weight 1.869).
    • Random Forest Classifier (model/rf_model.pkl): Bagged ensemble of 100 decision trees (max depth 4, balanced weights).
    • Support Vector Machine (model/svm_model.pkl): Soft-margin SVC with RBF kernel and Platt probability calibration.
    • Artificial Neural Network (model/diabetes_ann.pkl): Feedforward Multilayer Perceptron (MLP) with 8 → 32 → 16 → 1 architecture.
  2. Training Status: All four target models were successfully trained, cross-validated via 5-fold stratified CV, and pickled through train_and_evaluate_all.py.
  3. Artifact Synchronization: The serialized pickle files correspond directly to the latest tuning run. However, legacy JSON files (e.g. model/random_forest_calibrated.json, 4.95 MB with "accuracy": null, and model/svm_calibrated.json) remain as stale orphan artifacts from earlier experiments.
  4. Data Partitioning & Evaluation Integrity: All four models were benchmarked on the identical stratified 80/20 train/test partition (random_state=42, N=614 train, N=154 held-out test). The test set was locked away during tuning.
  5. Data Leakage Prevention: In train_and_evaluate_all.py, missing value medians and StandardScaler parameters were strictly fitted on X_train only. Threshold optimization used Out-Of-Fold (OOF) cross-validation on training folds. No data leakage exists in the main benchmark pipeline.
  6. Probability Calibration:
    • XGBoost: Well-calibrated log-loss probabilities (Brier score: 0.1663, best across all models).
    • SVM: Calibrated via Platt scaling (fitted sigmoid).
    • ANN: Raw sigmoid output probabilities (Brier score: 0.1668).
    • Random Forest: Simple tree voting (Brier score: 0.1760).
  7. Critical Frontend Discrepancies Discovered:
    • XGBoost Browser Inference: Highly accurate. Python and JavaScript probability differences are < 0.0001 across test inputs.
    • ANN Model Mismatch: In website/script.js (line 11), a hardcoded legacy 8 → 16 → 8 → 1 MLP is executed rather than the newly retrained 8 → 32 → 16 → 1 model stored in window.ALL_MODELS_DATA.
    • SHAP Attribution Mismatch: The client-side SHAP waterfall chart computes Integrated Gradients against the legacy ANN weights for all models, even when XGBoost or Random Forest is active.

TASK 3 — ROOT CAUSE ANALYSIS: WHY ACCURACY HOVERS AT ~76%

Key Finding: The ~76% performance ceiling is not primarily caused by model capacity or code bugs; it is driven by severe data omissions and statistical limitations inherent to the Pima Indians cohort.
  1. Extreme Missing Data Masked as Zeros:
    • Insulin: 48.70% missing (374 / 768 rows). Serum insulin was omitted for almost half the cohort.
    • SkinThickness: 29.56% missing (227 / 768 rows).
    • Univariate median imputation replaces 48.7% of insulin values with the constant 125.0 µU/mL. This creates an unnatural spike that destroys the physiological non-linear relationship between Glucose and Insulin (e.g. HOMA-IR index).
  2. Small Test Set Granularity ($N=154$): In a test set of 154 samples, a classification change for a single patient alters accuracy by 1 / 154 ≈ 0.65%. A 76% vs 73% difference corresponds to just 4 to 5 patients, which lies well within the 95% binomial confidence margin.
  3. Rigid Decision Thresholding in the UI: The frontend enforces a static 0.50 threshold. Because the cohort is imbalanced (65.1% negative), unweighted models like SVM and ANN lean conservative, resulting in a disastrous 53.7% recall. Operating SVM at threshold 0.25 boosts recall to 87.04%, but the UI provides no mechanism for clinicians to adjust operating points.
  4. Shallow Hyperparameter Search: GridSearchCV evaluated only 8 to 12 configurations per model. Finer tree pruning parameters (gamma, subsample, colsample_bynode) and deeper learning-rate decay schedules were not explored.
  5. Client-Side Approximations: Random Forest was truncated from 100 trees to 25 trees in the JS bundle to save file size. Furthermore, SVM Platt scaling parameters in JS were static hardcoded approximations rather than dynamically bound to the fitted probA_ and probB_ attributes.

TASK 4 — REVIEW OF RESEARCH NOVELTY

Assessment of Existing Research Documentation:

  • RESEARCH_PROBLEM.md is outdated: It was drafted early in development and only contemplated a simple Logistic Regression model with isotonic calibration.
  • MODEL_COMPARISON_REPORT.md is comprehensive: It provides a rigorous benchmark across all 4 architectures, evaluates clinical false negative costs, and provides global TreeSHAP rankings.
  • The Remaining Research Gap: Current XAI in the platform is purely descriptive (telling the user why their risk is high), but offers zero actionable clinical recourse (telling the user what minimal lifestyle changes would reduce their risk below the danger threshold).
Recommended Research Contribution: "Actionable Counterfactual Recourse & Decision Boundary Inversion"

Concept: Given a patient predicted at High or Moderate Risk (≥30%), the system computes the minimal clinically plausible intervention vector on modifiable biomarkers (ΔGlucose, ΔBMI, ΔBloodPressure) required to shift the patient into the Low Risk category (<30%), while locking unmodifiable factors (Age, Pregnancies, Pedigree).
Implementation Feasibility: Requires zero project rebuild and no model retraining. Because all 4 models already execute synchronously in client-side JavaScript, a constrained gradient or simplex search can compute the optimal counterfactual vector in <15 ms in the browser.

TASK 5 — FINAL AUDIT REPORT & PRIORITIZED ROADMAP

A. Existing Working Features

  • 4 Validated Machine Learning Models: XGBoost, Random Forest, Calibrated SVM, and ANN trained with zero data leakage.
  • Synchronous Client-Side Inference Engine: website/models_bundle.js enables instantaneous local and offline prediction without CORS or server dependencies.
  • Modern Sci-Fi Medical HUD: Isolated human holographic silhouette, SVG circular gauge, 2x4 biomarker input grid, and held-out test performance grid.
  • Interactive 3D Biological Scene: Three.js WebGL canvas displaying interactive neural network pulses and vascular blood flow linked to live glucose inputs.

B. Verified Model Results Summary

  • XGBoost Classifier is the objectively superior screening model: Test ROC-AUC of 0.8255, Recall of 79.63% (only 11 false negatives), F1 of 0.6992, Accuracy of 75.97%, and Brier calibration score of 0.1663.
  • ANN is the superior precision model: Test Precision of 64.44% and Specificity of 84.00%, but unsuitable as a solo screening engine due to a 46.3% false negative rate at standard threshold.

C. Methodological Problems Identified

  • Frontend SHAP waterfall chart displays legacy ANN Integrated Gradients regardless of whether XGBoost or RF is selected.
  • Frontend ANN execution uses obsolete 8 → 16 → 8 → 1 weights instead of the retrained 8 → 32 → 16 → 1 architecture.
  • Simple median imputation creates an artificial density spike across 48.7% of missing insulin entries.
  • Repository contains 4.95 MB of orphaned/broken JSON files with null metrics.

D. Missing Experiments

  • Multivariate Imputation by Chained Equations (MICE / IterativeImputer) comparison against median imputation.
  • Clinical Decision Curve Analysis (DCA) measuring Net Clinical Benefit across screening threshold probabilities.

E. Recommended Research Feature

Interactive Patient Recourse Engine: Client-side mathematical solver computing personalized minimal biomarker reduction targets required to cross into the low-risk zone.
